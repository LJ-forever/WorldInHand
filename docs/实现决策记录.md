## 2. 地图与移动

**D-05 地图形态与规模（A1）**
地图是一块凸的不规则岛屿，内部由 **Voronoi 多边形**铺满，不使用六边形网格。内置图 `cell_count = 400`（校验范围 150～800），合并后最终约 279 块；每格有唯一 `cell_id`、多边形顶点、中心、地形、高程、面积、POI 与邻接表。边界由带噪声的极坐标采样后取凸包生成，默认 72 个采样点、粗糙度 0.12。起点与终点不再取边界极值，而是在地图内侧 22% 的采样区域中寻找距边界至少 7.5% 短边的候选，再按 BFS 距离 14～30 格与空间距离评分选出一对内陆点。POI 默认 10 个，彼此及与起终点至少间隔 4 格。

> 修正记录：原定 20×20 六边形是为满足「起点→终点 25～35 格」，但用户确认要真实地图式的**不规则多边形**。改为 Voronoi 后，格数、边界形状、地形分布均由 JSON 配置驱动；起终点距离改用邻接 BFS 校验。地图不再有轴向坐标，存档与调试只记录 `cell_id`。
>
> 2026-10-23 二次修正：为满足「地块大小不一、不能太小也不能太大」，站点改为密度噪声保留 + 面积细化，平均地块变大，因此 BFS 距离区间由 25～35 调整为 16～28；地图不再要求整张一屏看清，改用滚轮缩放与中键平移查看细节（D-45）。
>
> 2026-10-24 三次修正：用户希望一次移动能遇到多个不同事件，因此把内置图 `cell_count` 从 460～500 降到 276～300，最终格数约 200～220，平均面积约 951 px²（旧版约 576 px²）；BFS 区间相应改为 10～20 格。单格 AP 按面积缩放，路线总 AP 与 wander 检查次数保持相近（D-51）。
>
> 2026-10-25 四次修正：用户要求地图更大、起终点不必在边界、但仍要能在 40 回合内结束。内置图 `cell_count` 调至 400（最终约 279 块），POI 10 个；起终点改为内陆采样对（距边界至少 7.5% 短边，BFS 14～30 格），生成后以 120 AP 可达性校验兜底。同伴另从玩家 3～6 格外的另一条路出发，序章解释走散原因（D-60）。

**D-06 地图配置与校验**
地图是**配置文件**而非逐格存档：`data/maps/*.json` 保存 `map_id / name / seed / randomize_seed / cell_count / bounds / boundary_* / terrain_weights / gradient / elevation / poi_count / hops` 等生成参数，运行时由 `MapGenerator` 重建。地块形状、起终点、POI 由配置与形状种子确定性生成；`randomize_seed = true` 时形状种子每局重掷，地形分布另由每局随机 `terrain_seed` 生长（D-47/D-53）。`MapConfigLoader` 扫描内置配置，支持 `hidden` 标记，并允许玩家从本地载入 JSON。

校验沿用并扩展 §5.6：格数 150～800、≥3 地形、无孤立格、全图可达、起点→终点 BFS 14～30 格、最短路径 AP ≤120、死区（无邻接格）≤15%、POI 数量与配置一致，并要求地块面积分布不过分极端（低于 0.22× 或高于 2.80× 平均面积的异常格不超过 4%）。失败递增种子重试，最多 12 次；仍失败使用内置 `DEFAULT_CONFIG`（种子 `20261023`）并继承原请求的角色/事件清单，兜底图也必须通过同一套校验。

**D-07 高差**
整数 0～4 层，噪声生成。MVP 只参与 AP 公式，不影响事件与侦察（§5.5）。

**D-08 AP 定点（A2）**
内部 `deci-AP` 整数：`0.1 AP = 1`。掷骰 `AP = (1d6 + 速度 + 装备AP加值) × 10`，上限 **120**。地形系数 ×10：平原 12、密林 20、沙漠 25。v1.4 起改为按实际路径连续结算：`像素距离 × 0.35 deci/px × 目标格地形系数 + 上坡高差 × 1.0 AP/级`，下坡不返还，绳索上坡减半（D-62）。旧版“单格最低 5 + 面积系数”已废止，面积只影响外观。显示 1 位小数。所有数据文件仍写人类单位（`-1` 表示 1 AP）。

**D-09 自由画线与路径结算（A9）**
玩家按住左键从角色所在格拖出任意折线，松开后：
1. 对原始轨迹按 2.5 px 间距加密采样；
2. 从角色格开始，按轨迹顺序映射为连续 `cell_id` 序列；
3. 若采样点跨到非邻接格，用最短路补齐，保证序列逐格相邻；
4. 显示用轨迹保留加密后的点串，移动动画沿该点串插值，而不是逐格中心跳格。

画线阶段**不计算也不显示**路径 AP 成本、能否到达、截断点或终点可达性；HUD 只显示角色状态与地图信息。路径不预扣 AP。右键清除路径，空格/回车/「沿路径移动」开始移动。

移动时按实际画出的路径连续累加消耗（像素距离 × 目标格地形系数 + 上坡高差，见 D-62）；付不起更远位置时沿成本曲线反解最远可负担点，停在线上而非吸回格心，已消耗 AP 不返还。格内移动同样扣 AP，只有进入新格才触发到达事件。设计文档原路径预览/截断提示口径由 A9 覆盖，待设计文档升版时同步（见 T-12）。

**D-09A 移动动画与到达事件（A10）**
移动由 `GameManager.advance_movement(delta)` 以 260 px/s 推进，表现层只读取 `visual_position`。AP 在推进过程中按实际路径距离连续扣除，不等到跨格才结算。跨入某格时：
1. 不额外扣整格 AP（该段已随距离扣过）；
2. 发出 `cell_entered(cell_id, from_id)`；
3. 调用 `EventManager.on_cell_entered(cell_id)`；返回 `true` 则暂停移动并进入事件状态，事件结束后可继续；
4. 若该格是终点，结算胜利占位。

事件钩子必须在**动画抵达该格**时调用，不能在开始移动时预结算。`EventManager.on_cell_entered` 命中事件时返回 `true`，移动进入 `EVENT` 状态并保留剩余路径；事件关闭后由 `GameManager._on_event_finished` 统一处理死亡、胜利、`trapped` 或继续移动。详见 D-49。

**D-10 AP 不足转 HP**
缺口换算成整 AP 时**向上取整**，1:1 扣 HP（如缺 0.5 AP → HP −1）。HP ≤0 立即走死亡流程。

**D-11 回合 AP 与 lost**
回合开始掷 AP；`lost` 在掷骰之后扣 20 deci（2 AP），`lost_severe` 扣 40 deci（4 AP），不足部分按 D-10 转 HP，然后清空。AP 不跨回合保留。状态在获得当回合不结算 AP 惩罚，下一回合掷 AP 后生效一次。

**D-12 休息**
不消耗 AP，恢复 1 HP；`trapped` 可用。玩家每回合最多 1 次；AI 同样，且休息后结束本回合。

**D-12A 回合内多次行动（T-13）**
一个回合不是「只能行动一次」：AP 是唯一预算。只要还有 AP，玩家可以在同一回合内反复行动（当前 P0 为多次画线移动与休息；后续物品/技能同样按 AP 结算），不需要先结束回合。休息不耗 AP 但每回合最多 1 次（D-12），休息后玩家仍可继续行动；「结束回合」用于主动放弃剩余 AP、进入下一回合并重掷 AP。AI 每个回合按自身规则行动，休息后结束本回合。

**D-13 随机流**
`RNGManager` 按用途分流：`map / event / ai / loot / combat`，子种子 = `hash(master_seed + 流名)`。同一形状种子 + 同一参数必须复现同一地块形状、起终点与 POI；地形分布由每局 `terrain_seed` 决定（A12/D-47），同 `terrain_seed` 时同样可复现。

## 3. 事件与检定

**D-14 触发优先级与队列**
`goal(4) > poi(3) > enter_region(2) > wander(1)`。同一回合最多结算 3 个随机事件（`goal` 不计入）；待触发队列容量 2；队列满时新触发按优先级替换最低者，被替换者**丢弃并记日志**。v1.5 起未开始的队列事件跨回合保留，不再在回合开始清空（D-64）。

**D-15 wander 粒度**
玩家每累计消耗 30 deci-AP（3 AP）做一次 13% 判定；判定后累计清零（无论成败）。v1.5 起另在每回合开始时对玩家所在地形做一次 24% 环境判定，归入 `wander`（D-64）。移动中途跨过阈值即判定，事件命中则暂停移动。

**D-16 事件冷却**
按事件 ID 全局冷却 2 回合（玩家与 AI 共享）。冷却中不可触发；强制触发仅限设计明确写出的情况。

**D-17 结算顺序**
严格按 §7.5：数值 → 死亡检查 → 物品 → 状态 → 标记 → 揭示 → 友好度 → 位置 → 事件链 → 胜负。数据里的效果先按此阶段归组，同阶段内按数组顺序执行。死亡检查失败即终止后续结算。

**D-18 检定与暴击**
`2d6 + 属性 + 装备属性加值 + 词条 + 状态`。暴击优先：**双 6 → 大成功；双 1 → 大失败**；否则按 `≥DC+5 / ≥DC / <DC / ≤DC−5`。自动成功/免疫跳过检定，且不触发大成功/大失败。

**D-19 幸运重投（A7、T-01）**
每局可用重投次数 = `幸运 // 2`，**不随回合回复**；每次重投重掷 2d6（保留原加值），消耗 1 次。加值、锁定不实现（P1）。

**D-20 幸运的「事件随机」（T-02）**
设计文档未定义基础幸运对事件数值的具体影响，MVP 先不实现基础幸运的随机修正；`rare_charm` 的 `luck_event +1` 记为事件数值骰加值（如 1d6 数量/损失），待设计确认。

**D-21 装备加值口径**
「装备加值总和」（防御 DC、薇拉/影的检定 DC）只计**属性加值**（战斗/交涉/感知/幸运/体力），不计专项检定加值（望远镜「侦察+1」、契约书「交涉+1」属于 `check_bonus`，不计入）。

**D-22 减伤与加损取整**
沙漠之子「伤害减半」按绝对值向下取整（−3 → −1）；贵族「被抢劫损失 +50%」仅作用于金币损失，向上取整（T-09）。

## 4. 侦察与信息

**D-23 侦察**
消耗 2 AP；`DC = 10 + 地形修正 + 高低差修正`（MVP 天气 0，高低差见 D-54）；成功半径 = 感知 // 2 + 1（至少 1 格，A17），按**地块邻接 BFS 距离**揭示半径内全部格子，不做视线遮挡；大成功半径 +1 并揭示最近 POI；大失败暴露位置 1 回合。

**D-24 揭示等级**
MVP 上限 3：侦察成功 +1；侦察大成功额外定位最近未探索 POI 并标记为已知；神秘石碑/终点守卫的交涉大成功 +1，均封顶 3。等级 4～5 标 P1。

**D-25 被影偷后追回**
玩家每回合可进行 1 次感知检定 DC 12，**免费、不消耗 AP**；成功归还物品，影友好度 −3（受 −5 下限截断）；追回不撤销影的任务完成状态。v1.7 已实装：`CompanionAI` 记录 `_stolen_item_id` 与 `_recovery_attempt_round`，`GameManager.recover_stolen_item()` 负责检定、发骰子动画、归还物品与自动存档；背包页在失物存在时显示「追查失物（免费）」，并说明本回合是否已尝试。归还走 A3 的 `grant_item()`，若玩家背包已满则进入溢出取舍。偷回后再次被偷会重新记录新物品。v1.8 起影的任务初始为中立，且任务完成前的偷窃失败好感下限为 −2（A24），否则她会在首次得手前就因失败转敌，令 D-25 在多数开局中不可达。

**D-26 生成与初始状态**
AI 从玩家未选的 4 人中随机 1 人；主隐藏任务从该角色 2 个 MVP 候选中随机；初始友好度在对应区间内按种子随机。v1.1 起 AI 不再与玩家同格，而是在玩家 3～6 格外的另一条可行路径上出发；序章会说明两人在岔路口走散的原因。玩家先行动。

**D-27 AI 背包**

**D-28 AI 决策**
枚举候选行动：移动 / 侦察 / 休息 / 使用物品 / 攻击 / 任务特殊动作（偷窃、施陷、分享）。按 §11.7 评分表 + 主任务权重 ×2 + 生存优先级。已探索区用 A*，未探索区按方向梯度估算。同分用 `ai` 流随机打破。

**D-29 AI 死亡（T-03）**
HP ≤0 视为退出本局（从场上移除）。**不计入抢先、不判玩家胜负**；其未完成任务不再判定。

**D-30 AI 物品与休息**
使用物品消耗 1 AP：优先 `supply` 回 HP，其次 `potion` 解负面状态；不用 `herb` 恢复。每回合最多休息 1 次，休息后结束回合；附近有敌人且 HP 过低时优先逃跑。

**D-31 影偷窃（T-04）**
每回合最多 1 次，消耗 1 AP。成功偷非消耗品装备（优先武器/饰品）→ 无则消耗品 → 都无则失败等待。成功即任务完成：影当时为敌方 → 玩家**立即失败**；友方/中立 → 友好度 −5 **强制转敌**（即使高好感扣到 −2，也按 §11.4 直接转敌），不立即失败。失败：影友好度 −2，本回合结束；按 §11.3 检查是否 ≤−3。v1.7 起 `_try_steal` 记录被偷物 `_stolen_item_id`，成功转移到影的 3 格背包；`player_defeated` / `defeat_reason` 由 `GameManager._run_companion_turn()` 转为 `GAME_OVER`，失物可通过 D-25 追回，但不会撤销任务完成。T-04 据此关闭。v1.8 起任务未完成且失败前为中立时，失败结算后好感下限为 −2，防止 D-25 窗口被连续失败提前跳过（A24）。

**D-32 薇拉施困（A6）**
与玩家距离 ≤1 时可发动，消耗 1 AP，每回合最多 1 次，每局最多成功 1 次。检定 `2d6 + max(交涉, 战斗)` vs `8 + 玩家感知 + 装备属性加值总和`。失败友好度 −2。任务完成判定窗口：玩家到达终点时仍 `trapped`，或终局/超时未到达终点。

**D-33 青蘅分享**
距离 ≤1 自动触发，每回合最多 1 次，不耗 AP；玩家背包满则失败且不消耗次数；成功玩家得 `herb`，青蘅友好度 +1。

**D-34 林鸮测绘**
「终点前 3 格」= 起点→终点最短路上的最后 3 格；只统计林鸮自己揭示的格子。「抢先揭示终点」要求林鸮先揭示且未分享。

**D-35 沙铠携带任务**
只认 `pelt / herb / ancient_coin / rare_charm` 中任一；初始弯刀不计入。

## 6. 胜负与流程

**D-36 回合上限（A5、T-05）**
单局 40 回合；第 40 回合结束玩家仍未通过终点守卫进入终点 → 判失败（超时）。

**D-37 先到奖励（A4、T-06）**
第一个通过终点守卫的角色获得金币 +20；同回合到达视为并列，均获得。奖励内容为临时裁定，不改动胜负。

**D-38 完美胜利**
到达时检查所有已在终点 AI 的「到达时阵营」：存在到达时敌方 → 失去完美；全是友/中立 → 保留完美。同回合并列按是否有「同回合到达的敌方 AI」判定。阵营快照必须在到达瞬间写入。

**D-39 终点守卫**
每角色独立触发；通过后该角色不再触发。使用物品献祭：不耗 AP，消耗任意非任务物品，**守卫本局永久离开**（对所有人，T-07）。AI 不能选使用物品；AI HP ≤3 放弃挑战，HP >3 可再次挑战；未通过不算到达终点。

**D-40 玩家死亡**
HP ≤0 立即失败（MVP 无第二条命，`has_second_life` 恒 false）。

**D-41 存档**
`user://saves/<slot>.json`，只存 `game_version + seed + state`；地图由种子重建。v1.5 已实现单槽自动存档，完整口径见 D-63。

## 7. UI 与内容

**D-42 中文字体**
用 `SystemFont`（微软雅黑/黑体/Noto CJK 回退），不把字体文件放进仓库。正式导出前换成可再分发的开源字体（P1）。

**D-43 UI 与逻辑分离**
UI 只读状态、发意图；结算全部在 Manager。移动动画由 `MapView` 读取 `GameManager.visual_position`；事件面板由 `EventPanel` 监听 `EventManager` 信号渲染，骰子由 `DiceOverlay` 监听 `GameManager.dice_rolled` / `EventManager.dice_rolled` 播放滚动动画（D-60），音效仍延后。面板：HUD、地图、事件、序章、手册、背包、骰子。

**D-43A 游戏内暂停与退出**
进入地图后不再提供「地图选择」入口，避免局内直接换图。底部栏改为「菜单（Esc）」；点击或按 `Esc` 打开暂停层，提供三项：
1. **继续游戏**：关闭暂停层并 `get_tree().paused = false`；
2. **返回主界面**：先尝试 `GameManager.autosave()`，再 `get_tree().paused = false` 并切换到 `main_menu.tscn`，主界面显示「继续游戏」（D-63）；
3. **退出游戏**：先尝试自动存档，再 `get_tree().quit()`。

暂停用 `get_tree().paused = true` 实现；HUD 所在 `CanvasLayer` 与暂停层均为 `PROCESS_MODE_ALWAYS`，保证暂停后按钮与 `Esc` 仍能响应。结算面板显示时不响应暂停。换地图只能回到主界面走「主界面 → 选择地图文件 → 选择角色」流程（A8）。

**D-43B 地块内非均匀高程**
规则层仍以整格为单位结算：每格有一个整数 `elevation` 代表值，AP、事件、POI、邻接都不因格内高程变化而改变。数据层不再把这一整数当作格内唯一数值，而是为每格生成一组格内高程采样：
1. 每个 Voronoi 顶点一个采样：本格高程与**共享该顶点的相邻格**高程取平均，再叠加连续 `FastNoiseLite` 细节；
2. 每条边的中点再插入一个采样，使格内存在次级坡面；
3. 采样结果写入 `elevation_samples`，并计算 `elevation_mean`、`relief_min / relief_max`；
4. `MapData.elevation_at(cell_id, point)` 对采样点做反距离加权，因此同一地块内不同位置会得到不同海拔；
5. HUD 悬停显示光标处的当地海拔与该格范围，例如「海拔 2.8（格内 1.7–3.3）」；范围过小则显示「格内平缓」。

渲染继续按多边形边界绘制，地块仍是操作单位；顶点颜色在共享边界按相邻地形颜色混合（24%，保留过渡但不至于把群系糊成一片），边中点取两端平均。内部 Voronoi 线只保留很淡的一层。

移动的爬升成本读取 `elevation_at(cell_id, point)` 的起止采样点；地形系数仍取目标格。事件、POI、邻接与胜负仍读整格 `elevation` 代表值。这样同一条路径在不同格内起点会产生不同成本，但事件判定不会因鼠标位置而漂移（D-62）。v1.8 起单段路径成本封顶 3 AP（D-67），玩家连续路径与 AI 格心近似共用这个上限。

`relief_polygon / relief_heights / elevation_samples / elevation_mean / relief_min / relief_max` 都由 `MapGenerator._build_relief` 运行时生成，不写入 JSON，也不进入存档。颜色按地图缓存，避免每帧重复计算。

**D-44 保持关闭的延后项**
个人胜利条件、完美胜利的个人条件、AI 指令、2 个 AI、次要任务、P1 的 5 个隐藏任务、potion 制作、relic、揭示等级 4～5、夜行者、重甲完整效果、商队出售、天气、昼夜。代码只留扩展点，不做半成品。

**D-45 地块面积变化与地图缩放（A11）**
地块大小不再由等距站点决定：
1. 候选站点按 `平均间距 × 0.74` 的抖动网格生成；
2. 低频 `FastNoiseLite` 密度噪声给出 25%～80% 的保留概率，保留少的区域形成大地块，保留多的区域形成小地块；
3. 生成后最多两轮细化：面积低于平均 0.46 倍的格子移除站点，高于 2.40 倍的格子内部补一个站点；
4. 最终校验允许 0.22×～2.80× 平均面积，超出范围的异常格占比不得超过 4%。

地块仍是规则结算单位；`cell.area` 只在生成期和冒烟测试中使用，不写入 JSON、不进入存档。地块变大后不再保证整张地图一屏可读，因此地图视图增加：
- `draw_set_transform(平移, 0, 缩放)` 统一变换整张地图；
- 滚轮以光标为锚点缩放，范围 0.6×～3.2×；
- 按住中键拖动画布，平移时至少保留 96 px 地图在屏内；
- `Home` 按顶部信息条与底部动作栏之间的可用区域重新适配并居中（v1.1 起不再固定 1.38×，见 D-48）。

所有鼠标输入先经 `_screen_to_world` 转成地图坐标，再参与画线、悬停与海拔查询；因此缩放/平移不会改变已画路径、地块命中或 AP 结算。绘制线宽、标记和玩家图标随地图一起缩放。

**D-46 凹地块与相邻合并（A13）**
Voronoi 单元本身必然是凸多边形，只靠站点无法产生凹形。生成器在铺满地块后追加一次合并：
1. 随机打乱地块，按 `CONCAVE_MERGE_CHANCE`（0.36）尝试与一个尚未被占用的相邻块合并；
2. 合并用 `Geometry2D.merge_polygons`，只接受**单轮廓**、面积基本不缩水、且确实含凹角的结果；两块合并后还有 `CONCAVE_THIRD_CELL_CHANCE`（0.28）继续吞并第三块，形成更明显的 L/U 形；
3. 合并后面积不得超过平均地块的 2.30 倍，避免出现巨块；
4. 合并结果会重新做顶点清洗：去掉过短边与近乎共线的顶点，并用 `Geometry2D.triangulate_polygon` 验证可渲染，防止 `draw_polygon` 报「triangulation failed」；
5. `cell.center` 取组内最大原始块的中心（必在合并多边形内部），`cell.polygon` 是合并后的轮廓，`cell.concave` 标记形状；`cell.bounds` 用于点选加速。

合并后重新构建邻接表；点选/悬停用 AABB + `Geometry2D.is_point_in_polygon` 判定，不再按最近站点。凹地块与普通地块在移动、事件、AP 上完全一致。冒烟测试要求凹地块占比 ≥8%，并验证全部地块/起伏多边形可三角化。

**D-47 每局地图重掷与中心生长（A12/A16）**
形状种子与生态种子分离。`GameManager.start_new_game` 对 `randomize_seed = true` 的配置先重掷形状 `seed`，再生成一个随机 `terrain_seed` 传给 `MapGenerator.generate(config, run_seed)`；`randomize_seed = false` 时形状仍由文件中的 `seed` 固定。内置图开启随机，因此每次进入新游戏，地块轮廓、数量、起终点、POI 与群系分布都会变化。`同种子重开` 会临时关闭 `randomize_seed`，保留当前地图。

地形生成不再逐格独立随机，而是从地图中心开始 BFS：
1. 中心格按基础权重随机定类型；
2. 每格权重 = `terrain_weights` 基础权重 × 0.90～1.10 抖动，再依次乘以方向梯度与邻格影响；
3. 方向梯度读 `gradient` 配置，低侧地形倍率 `1 + strength × 2.4 × (1-t)^1.7`，高侧地形倍率 `1 + strength × 2.4 × t^1.7`（`t` 为归一化坐标），平原在中部获得 `1 + strength × 1.8 × 中心权重` 的倍率；倍率增长明显快于邻格加成，因此大方向不会被局部成团逆转；
4. 邻格影响按已定型邻格计算：同类邻格每个使权重 ×1.55（两个即 ×2.10）；沙漠邻格使草原 ×1.50、森林 ×0.65；森林邻格使草原 ×1.20；平原邻格使沙漠 ×0.85。这样沙漠与森林之间自然出现草原过渡带，同类邻格又会把群系连成较大片；
5. 一次生长若缺少任一种地形，则换 `terrain_seed` 重试，最多 8 次；仍失败则强制把极值/中心格改为缺失地形，保证至少 3 种地形。

`map.terrain_seed` 记录本局实际使用的生态种子（写进 HUD/日志便于复现），不写入地图 JSON；`map.seed_value` 记录本局实际形状种子，随机地图每次进入都会不同。

**D-49 事件引擎落地口径（P0）**
设计文档给出规则，但以下触发/交互细节由实现确定：

1. **区域判定**：`enter_region` 不按「每跨一格」判定。开局时 `EventManager._build_regions` 按**地形连通分量**（同地形且邻接）生成区域 ID；玩家首次进入未访问区域的边界格时做 **60%** 判定（v1.5 起，D-64），命中后只触发一次，事件从当前地形池抽取。这样「进入新区域」对应生态区域，而不是每个格子。
2. **POI**：每个 `poi_id` 每局只在首次进入时触发一次；v1.5 起概率为 **100%**（D-64），不再补判，避免玩家在 POI 上反复踩点。
3. **wander**：每累计消耗 30 deci-AP（3 AP）做一次 **13%** 判定，判定后累计清零；v1.5 起另有每回合开始时 **24%** 的环境判定，归入 `wander`（D-64）。事件命中时移动暂停，剩余路径保留。随机事件关闭时（`random_events_enabled=false`）不累计。
4. **行动内事件预算**：`goal` 强制触发且单独处理；其他触发在一次移动行动中最多启动 2 个事件，两次启动之间至少累计消耗 3 AP，同一 `trigger` 在一次行动中最多 1 个，每回合最多 3 个随机事件。预算不够的条目留在队列，下一行动优先处理；v1.5 起未开始的队列事件跨回合保留，不再在回合开始清空（D-64）。
5. **终点守卫**：每个角色首次进入终点触发一次并计入本回合；失败被击退后再次进入可重复挑战，但只有首次计入 `_goal_counted`，避免事件统计膨胀。通过后 `player.goal_passed = true`，不再触发。
6. **队列溢出**：容量 2；新触发优先级严格高于当前最低项时替换并记录丢弃日志，否则直接丢弃新触发。相同事件 ID 不重复入队。
7. **加权抽取**：基础权重 × 地形匹配系数（`terrains` 含当前地形 ×1.35，含 `any` ×1.0，否则不入选）；冷却中的事件不进入候选。最近开始的 3 个事件进入防重复池：只要池中还有未在防重复池里的候选，就只在新鲜候选中抽取；全都刚出现时才允许重复。角色词条/装备/天气/阵营系数保留扩展点，MVP 只实现地形、冷却与防重复。
8. **交易/偷窃/献祭二级菜单**：选择后 `EventManager` 暂停结算并发出 `trade_menu / steal_menu / sacrifice_menu / heal_menu`；UI 只展示按钮，最终由 `resolve_trade_offer / resolve_steal_item / resolve_sacrifice / resolve_heal` 完成。交易失败不扣金币、不耗 AP；通缉状态直接禁用交易。
9. **自动成功/免疫**：`auto_success_if_trait` 跳过检定并取 `success`；`immune_if_trait` 应用空效果，结果显示「免疫」且不触发大成功/大失败。草药师对应草药丛，沙漠之子对应沙尘暴。
10. **效果顺序**：`_apply_effects` 按 D-17 阶段归组；HP ≤0 在数值阶段后立即设置 `_pending_death` 并跳过物品/状态/标记等后续效果。`enter_goal` 只设置 `_pending_goal_victory`，真正的胜负在事件关闭后由 `GameManager` 判定。
11. **死亡/胜利收口**：`finish_event()` 只负责冷却、清空当前事件并发出 `event_finished`；`GameManager._on_event_finished` 读取 `take_pending_outcome()`，死亡优先，其次胜利，再处理 `trapped`，否则恢复移动。
12. **调试开关**：`EventManager.random_events_enabled = false` 关闭 POI/区域/wander 随机触发，但保留终点守卫，供冒烟测试与手工调试；`debug_start_event(event_id)` 可直接打开指定事件。
13. **状态惩罚**：`apply_ap_penalties()` 在每回合掷 AP 后调用，处理 `ap_next_round` 与 `pending_ap_penalty_deci`；每个状态的惩罚只应用一次。`apply_round_status_effects()` / `tick_status_durations()` 在回合结束按 `added_round` 跳过快照，保证获得状态当回合不立即掉血或减持续。

**D-50 事件面板布局**
`EventOverlay` 作为 HUD 的 `CanvasLayer` 子节点，全屏半透明遮罩 + 居中 700 px 面板；事件未开始时隐藏。面板顶部为标题、触发类型/地形、描述，中部为骰子明细与结果，底部为动态按钮区。一次结算后选项按钮清空，只保留「继续」，避免重复选择；`Esc` 暂停菜单在事件进行中仍可用。

**D-51 大地块、面积 AP 与行动内事件节奏（A14；面积 AP 已由 D-62 取代）**
1. **地块尺度**：v1.1 内置图 `cell_count = 400`，最终约 279 块；`MIN_CELLS` 仍为 150。v0.5 曾把站点降到 276～300、最终约 200～220 块，让平均面积升到约 951 px²；v1.1 为满足“大地图、起终点在内陆、40 回合可完成”重新增加站点。v1.4 起面积不再参与 AP（D-62），仅保留内陆起终点与 BFS/可达性校验。
2. **面积 AP（v1.4 起废止）**：旧版 `MapData.move_cost_deci` 在原有地形系数 + 高差之后乘以 `clamp(sqrt(cell.area / 600), 0.70, 1.80)`。v1.4 改为实际路径距离连续计费，面积不再参与 AP（D-62）；此条仅保留为历史口径，避免与旧截图/旧存档对比时误判。
3. **行动计数**：`GameManager.execute_move` 调用 `EventManager.begin_action()`；移动结束、AP 不足停下、事件死亡/胜利、`trapped` 中断时调用 `end_action()`。事件在移动动画暂停期间仍属于同一行动，恢复后继续累计 AP 与事件数。
4. **2 个事件上限**：每次行动最多启动 2 个随机或目标事件；goal 守卫作为终点终局事件可无视该预算。两次事件开始之间要求 `当前行动累计 AP - 上次事件开始 AP ≥ 3.0`，因此同一格连续触发 POI + 区域事件时只会先显示一个，另一个至少要等跨过约 3 AP 的路径。
5. **同触发源上限**：一次行动中 `poi` / `enter_region` / `wander` 各自最多开始 1 个，避免同一条路线连续弹出多个 POI 或多次 wander。
6. **回合上限与队列**：每回合最多 3 个随机事件（goal 不计入）；队列仍为 2，溢出按原优先级规则丢弃；v1.5 起 `start_new_round()` 保留未开始的队列事件，只清零本回合计数与 wander 累计，队列仍受容量 2 限制（D-64）。
7. **防重复与内容覆盖**：最近 3 个已开始事件进入过滤池；同时新增 `fallen_tree`（森林/平原）、`mirage`（沙漠）、`pilgrim`（任意）三个 wander 事件，使森林、沙漠、平原都有至少 3 个 wander 候选，避免“某地形只剩迷路”时反复触发同一事件。
8. **测试口径**：回归已改为断言实际路径成本随距离增长、上坡额外加价、绳索减半；面积系数与旧的“格中心进入成本”断言随 D-62 移除。3 AP 间隔、单行动 2 事件上限、同触发源上限、每回合 3 个随机事件上限、goal 不受限，以及防重复池在存在替代项时过滤最近事件仍然覆盖。

**D-52 地图内容清单（A15）**
1. **清单字段**：地图 JSON 新增可选数组 `character_ids` / `event_ids`。数组顺序即角色选择界面的显示顺序；事件清单不改变各事件自身的触发类型、权重与冷却，只限定候选范围。
2. **运行时口径**：`GameManager.available_character_ids(config)` / `available_event_ids(config)` 是唯一读取入口；角色选择界面、AI 对手抽取、`EventManager._pick_weighted_event` 全部经过它。`start_new_game` 会拒绝不属于该图清单的角色，避免绕过菜单直接开局。
3. **省略兼容**：字段缺失或非数组（旧地图/本地临时地图）回退到全量内容；字段存在但为空、重复或引用不存在的 ID 时，`MapConfigLoader.validate_config` 直接判错，防止“以为限制了其实没限制”。
4. **终点守卫**：`goal_guard` 仍由 `GameManager`/`EventManager` 代码强制触发，不依赖它是否出现在 `event_ids` 中；但内容清单应显式列出它，便于阅读与后续校验。
5. **当前内容策略**：唯一内置图 `borderland.json` 列全 `characters.json` 的 5 名角色与 `events.json` 的 15 个事件。这样单图即可回归全部效果，不要求玩家为了测试不同内容切换地图；地图差异由每局随机生成提供（D-53）。
6. **风格扩展**：未来新增西幻、玄幻等风格时，复制一份地图 JSON，调整生成参数并替换清单中的角色/事件 ID 即可；角色与事件仍存放在全局内容表中，由清单引用，不复制数据。
7. **与随机地图的关系**：内容清单固定属于某张地图 JSON，不随形状种子变化。唯一内置图每局重掷形状种子，但清单仍是同一份；随机的是地图内容，不是角色/事件池。
8. **界面提示**：地图卡片显示角色/事件数量；角色选择顶部显示「地图 · 种子 · 地块 · POI · 角色数 · 事件数」，随机地图的种子位置显示「每局随机」，让玩家在开局前就能确认本图内容范围。
9. **测试口径**：回归测试覆盖内置图清单完整性、子集清单过滤、清单外角色开局拒绝、AI 仅从清单抽取、事件抽取不越界、缺省字段回退全量、未知 ID 校验失败，以及角色选择界面按清单显示按钮。

**D-53 单张地图每局重新生成（A16）**
1. **只保留一张**：删除 `red_dunes.json`、`black_forest.json` 与兜底地图文件，`data/maps/` 只保留 `borderland.json`；地图选择界面不再生成单独的「随机地图风格」卡。
2. **字段**：`borderland.json` 设 `"randomize_seed": true`。`MapConfigLoader` 校验该字段必须是布尔值；缺省视为 `false`，固定地图仍按文件 `seed` 复现。
3. **开局重掷**：`GameManager.start_new_game` 先复制传入配置，再对 `randomize_seed = true` 的配置调用 `_roll_map_seed()` 替换 `seed`，因此不会修改 `MapConfigLoader` 缓存的原始配置。随后 `MapGenerator.generate` 用新形状种子重建地图，生态种子仍单独随机。
4. **实际变化范围**：形状种子影响海岸线、Voronoi 站点、地块面积/数量、凹地块合并、POI 选取、起点/终点与高程噪声；生态种子影响三种地形的分布与渐变。两者叠加后，每次进入游戏的地图轮廓、路线长度、事件位置与视觉都不同。
5. **重开语义**：`restart_same_seed()` 会把配置里的 `randomize_seed` 临时设为 `false`，再按当前 `map.config` 的种子重建，保证「同种子重开」真的同图；从菜单重新选图、选角色进入则再次重掷。
6. **界面**：地图卡片显示「每局重新生成」；角色选择顶部显示「种子 每局随机」；进入游戏后 HUD 显示本局实际形状种子与生态种子，便于复盘。
7. **兜底**：删除兜底文件后，生成连续失败时 `MapGenerator` 使用内置 `DEFAULT_CONFIG`（固定种子与参数），并继承原请求的 `character_ids` / `event_ids`，避免兜底图绕过内容清单。
8. **测试口径**：回归测试断言内置地图恰好 1 张、`randomize_seed` 为 true、连续两次开局的形状种子不同、地图签名（地块数/起点/面积和/终点）不同、原始配置不被修改，以及 `restart_same_seed` 保留当前种子。

**D-54 圆形迷雾三态、被动视野与侦察扩张（修订）**
1. **三态定义**：显示状态只有三种：`VISIBLE`（格心在当前视野圆内，最亮）、`REMEMBERED`（`seen` / `scouted` / `entered` 之一，但当前不在圆内，压暗）、`UNKNOWN`（从未获得信息，近黑覆盖）。不再区分「已侦察」「已进入」的显示层级：主动侦察和踏足只影响“是否记得”，不影响当前可见性。迷雾标记只存在于运行时 `MapData.Cell`，不写地图 JSON、不写存档。
2. **圆形视野**：基础视野不再按 BFS 格数计算，而是以玩家所在格中心为圆心、`average_cell_size × 2` 为世界半径的圆。`current_vision` 只记录格心在圆内的格子并标记 `seen`。渲染层对每个地块执行 `polygon − vision_circle` 裁剪，只给圆外部分上雾，因此**圆弧会切过边缘地块**，不会出现“擦到圆边就整格点亮”。被切到但格心在圆外的地块不会获得整格记忆，只保留圆内局部的当前可见。
3. **分层渲染**：每个地块先无条件绘制完整地形底色与起伏，再叠加雾层。`REMEMBERED` 使用 alpha 0.56 的低亮度记忆雾，`UNKNOWN` 使用 alpha 0.92 的近黑未知雾，故意保留少量底色透出。这样同一地块始终保留基础地形色，迷雾是覆盖层而不是替换色；玩家在未知区也能隐约看出地形轮廓。悬停按光标点是否在圆内判断：圆内显示「可见」，圆外的记忆格显示「记忆」，其余显示「未知」并隐藏地形/海拔。POI 标记只在可见或记忆状态绘制。
4. **平滑表现**：`GameManager` 维护 `vision_center_display` 与 `vision_radius_display`，在 `_process` 中分别以约 12/s 与 2.6/s 的指数缓动跟随真实视野；`MapView` 检测圆变化后重绘。移动时圆心平滑跟随角色，侦察扩张/收缩时半径平滑变化，避免视野瞬间跳变。
5. **侦察检定**：消耗 2 AP；`2d6 + 感知（基础）+ 装备加值 + 状态加值` 对抗 `DC = 10 + 地形.scout_dc_mod + 高低差修正`。高低差以整格代表 `elevation` 判断：≥3 为高处，DC −2；≤1 为低处，DC +2；其余为平地，0。`acrophobia` 在目标格为高处时把 −2 抵消为 0。侦察使用独立 `scout` 随机流，不触发随机事件。
6. **结果分级与扩张**：自然 12 或总值 ≥ DC + 5 为大成功；自然 2 或总值 ≤ DC − 5 为大失败；总值 ≥ DC 为成功；否则失败。成功扩张格数 = `max(1, effective_perception() // 2 + 1)`（A17），大成功再 +1。扩张值写入 `vision_boost_cells`，并按 `average_site_spacing` 换算成世界半径，追加到基础圆之外。`effective_perception()` 只计基础感知与状态里的 `perception` 修正，望远镜的 `scout_check_bonus` 只加检定、不加半径。
7. **保持与收缩**：扩张视野先保持 `SCOUT_VISION_HOLD_ROUNDS = 2` 个回合；之后每次 `end_turn` 使 `vision_boost_cells` 减少 `VISION_BOOST_DECAY_PER_ROUND = 0.5`，并重建视野与刷新迷雾，直到归零回到基础圆。重复侦察取当前扩张与新结果的较大值，并把保持回合重置为 2。
8. **大成功/大失败**：大成功把最近一个尚未探索、未进入、未揭示的 POI 标为已知；所有成功使 AI 揭示等级 +1，封顶 3（D-24）。大失败不扩张视野，把 `position_exposed_until_round` 设为当前回合 +1，在下一回合结束前所有 AI 都知道玩家坐标；普通失败只扣 2 AP。
9. **AP 与状态**：AP 不足 2 时侦察被拒绝且不扣 AP；移动动画、事件暂停、非 `PLAYING` 状态均不可侦察。侦察不推进回合。HUD 显示本次检定明细，以及成功后的「视野 +N 格」「保持回合/收缩中」状态。
10. **测试口径**：headless 回归覆盖圆形半径与格心判定、圆切过地块但未覆盖格心、开局迷雾比例、无初始记忆、终点不在初始圆内、高地/低地/恐高 DC、地形 `scout_dc_mod`、中毒 −1 检定与半径不变、确定性侦察骰、2 AP 消耗、扩张值/世界半径换算、2 回合保持、每回合 0.5 格收缩、最终回到基础圆、AI 等级封顶、大失败暴露、AP 不足拒绝、离开圆后转记忆、进入格在圆外也转记忆、显式揭示 POI、分层迷雾绘制，以及 HUD 未知/记忆悬停与侦察提示。

**D-55 隐藏任务分配与展示边界（A18）**
1. **候选池**：每名角色在 `characters.json` 的 `hidden_task_ids` 中列 3 个任务，其中 `hidden_tasks.json` 标记 `mvp_available = true` 的 2 个进入 MVP 候选池；P1 任务不参与。任务文本是 AI 同伴视角（如「与玩家友好度达到 +3」「偷走玩家关键装备」），因此不能直接作为玩家个人目标。
2. **玩家侧**：`GameManager.start_new_game` 只把所选角色的 2 个 MVP 候选记录到 `GameManager.player_hidden_task_candidate_ids`，不抽具体任务，也不写入 `ActorState`。按设计文档 §10.5，玩家隐藏任务在 MVP 只记录、不判定、不参与胜负；暂停菜单与旅途手册显示「隐藏任务：MVP 未启用」，不展示任何 AI 任务文本。
3. **AI 侧**：用独立随机流 `hidden_task_ai` 从 AI 角色的候选池抽 1 个，写入 `GameManager.ai_hidden_task_id`；对玩家保密。`CompanionAI.setup()` 读取该任务的 `initial_faction` 与 `initial_favor` 初始化阵营/好感，`take_turn()` 再按 `completion.type` 选择意图（D-56）。HUD 的「情报」等级是独立展示项，不直接泄露 AI 任务。
4. **修正记录**：上一版把玩家角色的候选随机抽 1 个显示，导致玩家会看到「与玩家友好度达到 +3」这类 AI 视角任务。该显示已移除（A18 修订）。
5. **数据校验**：`DataManager` 已校验角色引用的任务存在且 `character_id` 一致；`GameManager.mvp_hidden_task_ids()` 再过滤 `mvp_available` 与归属，保证候选有效。
6. **测试口径**：回归覆盖每角色恰好 2 个有效 MVP 候选、玩家侧记录 2 个候选且不抽具体任务、AI 获得归属正确的 MVP 任务、AI 任务 ID 保存、HUD 显示 MVP 未启用而非 AI 任务名、暂停菜单解释「只记录」。

**D-56 AI 同伴完整回合、阵营与信息边界（A19）**
1. **不是挂件**：`CompanionAI` 持有自己的 `ActorState`、隐藏任务、阵营、好感、位置、活动、最后已知位置与回合状态。每回合结束由 `GameManager._run_companion_turn()` 调用一次，独立掷 AP、结算持续伤害/状态、低血用药、挣脱陷阱，然后才选意图；不占玩家 AP，也不要求与玩家同格。
2. **任务驱动**：意图来自 `hidden_tasks.json` 的 `completion.type` 与阵营。友方援助类任务走向玩家靠拢的 `support`；敌方 `steal_equipment` / `player_trapped_at_window` 走 `hunt`；中立/竞争的 `reveal_goal_first` / `reach_goal_first` 走 `scout` / `goal`；其余未实现或探索型任务走 `explore`，搜完 POI 后转向终点。**支援优先靠近**：玩家无负伤/被困但 BFS 距离 >3 时，先向玩家靠拢；距离 ≤3 后才由 `_support_fallback()` 在侦察、探索拾取与望风之间选择。单回合最多 6 格，避免移动节奏只有玩家的一半；P1 任务没有专门判定时会安全回退，不会让 AI 卡死。
3. **移动与互动**：每回合最多 6 格，按同一套地形/距离/高差成本扣费（AI 决策使用格心到格心的近似，见 D-62）；探索可直接踏入 POI 并按地形拾取物资，援助/敌对靠拢时停在相邻格，避免与玩家完全重叠。互动范围是 BFS 距离 ≤1；援助会分享草药、解毒、包扎、分补给或交谈，敌对会偷非任务装备/物品或设置 `trapped`，失败也会产生可见反馈。
4. **阵营与好感**：好感范围 −5～+5；`favor <= -2` 敌对、`favor >= 2` 友好，其余中立。初始值与 `initial_faction` / `initial_favor` 一致，之后由事件 `ai_favor`、援助、偷窃失败/成功、下套等改变。跨越阈值时写入世界纪事，事件结算也按情报等级给出「眼神变了」或明确「转为敌对/友好」。
5. **视野外仍行动**：AI 在玩家圆形视野外继续移动、搜物资、侦察和推进。玩家只看到视野内行动文本；视野外以 45% 概率给环境传闻，并保留最后已知位置。`last_known_cell` / `last_known_round` 在回合开始或结束「可见或可听见」时刷新，玩家端最多保留 4 回合；超过后只显示「踪迹已经模糊」，不继续追踪。3 格内可听见时地图标记跟随她的真实位置，更远才固定在最后感知到的格子。
6. **情报分级**：0 级只给「态度有些变化」，不暴露数值；1 级显示好感变化；2 级显示阵营色、敌方警告短线与最后已知方向；3 级显示任务名、进度和精确好感。`companion_is_visible()` 只看当前圆形视野，`companion_at_player()` 只看 BFS 距离，两者互不替代。
7. **共享视野**：友方同伴每 2 回合共享自身周围 `scout_reveal_radius` 的地块，只标记「曾获得信息」（`seen`），不扩大玩家当前圆形视野，也不点亮未知黑区。共享文本写入纪事。
8. **旅途纪事与同伴台词**：`GameManager.world_log` 统一记录开局、玩家事件、可见 AI 行动、传闻、任务完成、阵营变化、死亡、终点竞争与共享视野，单条带回合号，最多 30 条；HUD、暂停菜单与结算共用。重复行会被去重，避免同一 AI 文本刷屏。每次 AI 行动结束由 `_pick_speech()` 按意图、阵营与玩家处境（被困/低血/中毒）生成一句台词，写入 `last_speech`；底栏同伴条只在 `companion_is_perceived()`（视野内或 3 格内可听见）时显示原台词，更远显示「她在远处，听不见她说话」，避免隔空对话。地图标记同样按可见/可听见/最后已知/未知四档绘制。
9. **终点与死亡**：AI 通过守卫成功时写「先你一步抵达」，并作为玩家胜利结算的叙事后缀；P0 仍不据此判玩家失败（T-03）。AI 在守卫失败/事件波及/持续伤害中死亡会标记 `alive = false`、写纪事并落灰色叉号；玩家端不再显示其实时行动。
10. **动态名字**：所有 AI 相关文本、HUD、事件结算使用 `companion_name()` / `_name()`，不硬编码「青蘅」；截图与测试也按实际 AI 角色断言，避免顶栏名字与叙事不一致。
11. **测试口径**：回归覆盖同伴创建/起点/任务/初始阵营与好感区间、友方分享草药并完成任务、敌方偷装备并完成任务、`ai_favor` 改变好感、情报 0/1 的显示边界、`ai_effects` 仅相邻生效、6 回合独立推进终点、远距离支援优先靠近、每回合台词、3 格听觉与远距离静音、四档地图标记、菜单按钮真实点击、公式逐项来源、视野外最后已知与情报不足、纪事上限与最新条目。

**D-57 4X 式事件编排、情境权重与选择可读性（A20）**
1. **软加权而非硬锁**：`EventManager._context_weight()` 在基础权重、地形匹配、冷却与防重复之后，按 HP 比例、通缉、剩余回合、同伴距离/阵营调整权重，最终 `clamp(0.2, 2.0)`。负伤时补给类更常见、危险类更少；被通缉时商队权重降到 0.35、危险类略升；临近 40 回合日落时危险/情报类降低、社会/补给类升高；敌对同伴相邻时危险类升高，友方相邻时社会类升高。它不绕过地图 `event_ids`，也不保证某事件必出。
2. **局势提示**：`get_context_note()` 在事件面板顶部用一两句话解释压力来源：负伤与具体 HP、通缉导致商队拒绝交易、剩余回合、同伴在侧/在附近/敌意目光。同伴提示只在同格/相邻时出现，且敌方「不善的目光」要求情报 ≥2，避免全知视角。
3. **风险标签**：`_risk_label()` 只看 DC 与失败后果，不把成功收益算进去。失败 HP 损失/负面状态/通缉累计达到 3，或 DC ≥14 为「高」；任一次要后果或 DC ≥11 为「中」；否则「低」。因此同一选项在不同内容数据下标签会随后果变化。
4. **悬停提示（D-62 起废止）**：`_choice_hint()` 曾把成功/失败结果翻成短句（HP/AP/金币/物品/状态/标记/好感），最多 4 项；`_choice_warning()` 曾在当前 HP 下判断失败是否致死、负伤是否危险，并在结果含 `ai_effects` 且同伴相邻时提示「结果也会影响她」。v1.4 起这些字段不再生成，选择前只保留风险档位，结果只在结算后展示。
5. **同伴效果边界**：`ai_effects` 只在同伴与玩家同格/相邻时结算，整组跳过远处同伴；具体伤势、物品、状态文本只在同伴当前可见时显示。`item_gain.choose_from` 交给 `CompanionAI.choose_event_item()`，`ai_task_aware = true` 时优先拿任务需要的可交易物。`ai_favor` 不受距离限制，直接改变好感/阵营，是关系变化而非“波及”。
6. **结果与纪事**：事件开始时写纪事；玩家效果先结算，玩家存活后才结算 `ai_effects`；`ai_favor` 在效果阶段统一应用。同伴被事件打死后由 `GameManager.mark_companion_dead("事件波及")` 收口，保证纪事、标记与 HUD 同步。
7. **测试口径**：回归覆盖负伤时增益/危险事件权重升降、局势提示包含伤势/同伴/剩余回合、马匪高风险的「中」标签、成功/失败提示、低血致死警告、低 DC 社会检定「低」、同伴波及警告、商队失败同时伤害相邻同伴、`ai_favor` 与情报显示、`_resolve_outcome` 结果文本含同伴名，以及静态 `ai_effects` 不波及远处同伴。

**D-58 主动战斗、反击与战斗面板**

1. **统一规则**：玩家与 AI 都调用 `CombatRules.resolve_attack(attacker, defender, rng)`，避免两套伤害/AP 公式。攻击者需至少 1 AP（10 deci-AP），先扣 1 AP 再做检定。
2. **检定**：`2d6 + 战斗 + 攻击方装备战斗加值 + 状态检定修正` 对抗 `8 + 防御方体力 + 防御方装备防御加值`。防御加值只统计六项基础属性与同名装备字段，侦察/交涉专用加值不计入（设计 §12.1）。
3. **结果**：大成功（含双 6）1d6 伤害；成功 1d3；失败攻击者额外 −1 AP，AP 不足转 1 HP；大失败（含双 1）攻击者再 −1 HP。伤害直接扣 HP，不经过 `statuses`。
4. **敌方 AI 出手**：敌方任务（偷装备/下套）未完成时仍优先做互斥任务；任务完成或目标不在手边后，相邻且冷却结束就攻击。好感 ≤−3 且自身 HP 过半时，会在 4 格内主动逼近。攻击后 `_hostile_cooldown = 2`，与偷窃/下套共用冷却。
5. **玩家先手**：HUD「袭击（1 AP）」只在相邻、敌方、玩家 AP ≥1、非移动时启用。玩家先检定；目标存活且为敌方时，若其 AP ≥1 会立刻反击一次，目标倒下则走 `mark_companion_dead`。AI 主动袭击后玩家选择反击时，该 AI 本回合已经出手，不再反击（D-64）。
6. **交互边界**：AI 袭击后 `GameManager` 进入 `State.COMBAT`，战斗面板展示两次骰值、加值、DC 与文字结算；玩家选择「消耗 1 AP 反击」或「承受这一击」，随后看结果再点「继续」。战斗期间暂停其他行动；关闭后恢复 `PLAYING`，若袭击发生在回合结束流程中则继续补完回合尾部。无 UI 的自动流程（测试）默认承受，避免等待输入。
7. **测试口径**：覆盖攻击检定/AP 扣费/防御 DC、AP 不足拒绝、敌方同伴相邻袭击、玩家主动袭击与反击、交互面板进入/选择/关闭状态机，以及 HUD 按钮与提示。

**D-59 到达快照、同回合冲刺与先到奖励**

1. **到达记录**：`GameManager.goal_arrivals` 按 `{actor, name, round, faction_at_arrival, rewarded}` 记录每次通过守卫；每个角色只记第一次。`first_goal_round` 是首次到达的回合，`round == first_goal_round` 的到达者都获得 +20 金币。
2. **阵营快照**：`CompanionAI.faction_at_goal` 在 `_attempt_goal` 成功瞬间写入当时的 `faction`。之后即使因事件/好感转敌对，也不追溯改变到达时阵营。
3. **同回合冲刺**：玩家通过守卫触发 `_finalize_victory` 时，若同伴存活且尚未到达，给她一次 `goal_race = true` 的额外回合；该回合只允许赶路/尝试守卫，不再袭击、偷窃或侦察。这样同回合到达能形成并列，而不是按玩家先点按钮的顺序直接判负。
4. **完美/基础**：玩家结算时，若任一同伴 `reached_goal == true` 且 `faction_at_goal == "enemy"`，则为「基础胜利」；否则为「完美胜利」。友方/中立先到不降低评价。AI 未通过守卫、被击退或死亡都不算到达。
5. **叙事与界面**：结算理由包含先到奖励、谁先到、是否同回合、基础/完美说明；HUD 标题直接显示「完美胜利」或「基础胜利」。AI 先到只决定奖励与分层，不在 AI 到达瞬间直接判玩家失败（T-03）。

**D-62 距离制 AP、格内移动与选择后揭示结果（v1.4）**

本轮把 AP 从“进入地块的门票”改成“沿真实路径持续消耗的预算”，并取消事件选择前的结果剧透：

1. **连续距离成本**：`MapData.segment_move_cost_deci(from_point, to_point, from_cell, to_cell, actor)` = `两点像素距离 × 0.35 deci/px × 目标格地形 movement_coefficient` + `max(0, 目标点海拔 − 起点点海拔) × 10 deci/级`。海拔由 `elevation_at()` 在格内连续采样，因此同一地块内的不同起点也会有不同爬升成本；下坡不返还 AP。绳索把上坡部分乘以 0.5。地块面积不再参与 AP。
2. **格内移动合法**：`set_drawn_path()` 不再要求 `path_cells.size() >= 2`，只要求路径长度 ≥ 6px。整条线都在当前格内时 `path_cells` 只有当前格，仍然可以执行；每画一条新线都会重新按实际路径扣 AP，因此可以在同一格内反复移动直到预算耗尽。
3. **成本曲线与连续扣费**：画线结束时同步生成 `move_point_distances` 与 `move_cost_samples`，两者与 `move_points` 等长。`_cost_at_distance()` 在折线上做线性插值；`_advance_to_distance()` 只对“本次已走到的新距离”收费，`_movement_charged_deci` 防止重复扣费。每帧扣费通过 `ap_changed` 让 HUD 只刷新 AP 文本，避免整页重绘。
4. **AP 耗尽落点**：若目标点的累计成本超过剩余 AP，`_distance_for_cost()` 反推出可支付的路径距离。角色先被放到该点的实际坐标，再 `_stop_movement(..., false)`；`player.cell_id` 保持最后真正进入的格子。消息为「AP 不足，停在路径上的实际位置（剩余 X AP）」，不再提示“下一格需要多少”，因为成本是连续累计的。
5. **事件与 wander**：`cell_entered` 只在跨入新格时触发，格内移动不会刷到达事件。每次实际扣费仍调用 `EventManager.on_ap_spent()`，所以“每累计 3 AP 做一次 wander 判定”的口径不变，格内移动也会累积触发预算。
6. **近/远边界差异**：进入 B 格的成本取决于从 A 格的哪个位置起笔。靠近共享边界的起点只需走很短一段；远离边界则要先穿过 A 格。玩家画线、视觉位置与成本曲线使用同一组点，保证“看到走到哪、AP 就扣到哪”。
7. **AI 口径**：同伴寻路与 `reachable_cells()` 仍用 `move_cost_deci(from, to)` 的格心到格心近似，逐格扣费；这是 AI 的简化决策成本，不复现玩家完整画线。`reachable_cells()` 继续用于生成校验与粗略可达性。
8. **选择前不剧透**：`_describe_choice()` 只返回 `text / check_text / risk / disabled / reason / resolution`，删除 `hint`、`preview`、`warning` 及 `_choice_hint()`、`_outcome_preview()`、`_resolution_preview()`、`_choice_warning()`、`_effect_summary()`。事件面板只渲染选项按钮与风险颜色；检定完成后 `_resolve_outcome()` 才实际施加效果，并把得到的物品、状态、HP/AP/金币、同伴影响等写入 `effect_messages`，由结算页展示。马匪伏击选择前只看到「战斗 / 交涉 / 逃跑」，战斗成功后才显示「获得「马匪弯刀」」。
9. **保留项**：D-61 第 1 条“AP 不足不吸附格心”和 `TOKEN_GRAB_RADIUS` 边界起笔保留；D-61 第 2 条四档结果预览和第 3 条面向玩家的 warning 口径由本条废止。`risk` 仍按 DC 与失败后果计算，只表示危险档位，不泄露具体收益。
10. **测试口径**：覆盖格内单格路径、格内 AP 连续下降、同一格反复移动、格内 AP 耗尽落点、近边界 vs 远边界的入口成本、实际路径总成本；所有选择在描述阶段不含 `hint/preview/warning`，马匪成功结算后才出现「马匪弯刀」并真正入库；事件界面选择前无结果 Label。

**D-63 单槽自动存档与继续游戏（v1.5，P0 验收第 9 项）**

本轮补齐存档读档。D-41 的路径与版本字段继续有效，以下清单取代其“只存 seed + state”的简写：

1. **格式与兼容**：存档写在 `user://saves/auto.json`，顶层包含 `format: "zhenming.save"`、`save_version: 1`、`game_version`、`saved_at`、`meta`、`map`、`player`、`companion`、`events`、`rng`、`game`。`SaveManager` 只接受格式标识与 `save_version` 完全匹配的存档；缺失、损坏 JSON、顶层非对象或版本不符都返回中文错误，不修改当前运行中的游戏。写盘先写 `.tmp` 再替换正式文件，避免中途退出留下半个 JSON。
2. **地图重建**：`map` 保存本局实际生效的 `config`（可能是生成失败后的兜底配置）、`generated_seed`、`terrain_seed`、`seed_value` 与迷雾数组。读档调用 `MapGenerator.generate_exact(config, generated_seed, terrain_seed)` 一次生成，不经过 `generate()` 的重试/兜底分支，因此同存档必定得到同一张地图；起终点、POI、多边形、高程都随种子恢复。静态角色、物品、事件定义不复制进存档。
3. **状态范围**：`player` / `companion.actor` 使用 `ActorState.to_dict()`，含属性、词条、装备、背包、状态剩余回合与施加回合、标记、HP/AP、金币、所在格、休息/任务进度与 AP 惩罚；`companion` 另存任务 ID、阵营、好感、存活/到达终点、当前动向、台词、最后已知位置、回合计数、互动冷却、访问过的 POI 与战斗摘要。`events` 保存队列、冷却、本回合/本行动计数、wander 累计、已访问 POI/区域、已揭示 POI、上一地形、揭示等级、终点尝试与事件日志；区域 ID 在读档时按重建地图重新推导。
4. **RNG 一致性**：`rng` 保存 `master_seed` 与每个命名流的 64 位 `RandomNumberGenerator.state`，state 用十进制字符串序列化，避免 JSON 浮点/int 精度损失。读档恢复事件流、AI 流等全部流后，下一次抽取与不中断游戏时一致，防止读档改变后续事件与 AI 行为。
5. **安全存档点**：`GameManager.can_save_game()` 仅在 `PLAYING`、序章已关闭、`is_moving` / `movement_paused` 为假、没有活动事件、没有战斗面板状态时返回 true；已画好但尚未执行的路径允许保存（路径是瞬时输入，不写入存档）。自动写入点：关闭序章、移动停止、回合结算完成、侦察成功/失败、休息完成、战斗关闭、事件关闭后恢复移动，以及暂停菜单“返回主界面/退出游戏”。进行中的事件、移动与战斗不会被写入。
6. **读档恢复顺序**：先校验地图/游戏/玩家/同伴结构并重建地图，再恢复事件编排与 RNG，创建并载入同伴，最后套用玩家、世界纪事、终点记录、视觉位置与视野扩张。`_restore_runtime_clean_state()` 清空旧路径、移动、战斗与暂停字段，避免上一局残留。读档后强制 `intro_open = false`，直接回到 PLAYING。
7. **迷雾精确保留**：读档先按恢复后的玩家位置重建 `current_vision`，再把所有格子的 `seen/scouted/entered/poi_known` 清零并按存档数组逐格置位；不会让视野重算额外点亮地块，也不会从 `entered` 推断 `seen`。因此读档画面与存档瞬间的记忆边界一致。
8. **入口与结束**：主菜单通过 `SaveManager.peek_save()` 读取元信息（不改变当前状态）显示「继续游戏 · 第 N 回合」，点击后 `load_game()` 成功才切换游戏场景，失败在菜单内显示错误。开局成功会清掉旧自动存档；胜利或死亡时 `_finish()` 先清除自动存档，避免读档回滚结局。`project.godot` 与 `SaveManager.GAME_VERSION` 当前统一为 `1.8`（v1.5 实装时为 `1.5`）。
9. **测试口径**：冒烟测试构造一局可玩状态，改动玩家/同伴/事件/迷雾/视野与 RNG 后存档，再污染运行时状态并读档，断言地图校验和与起终点、迷雾四类标记、玩家 HP/AP/金币/背包/状态/标记/位置、同伴任务/阵营/好感/台词/冷却/访问记录、事件冷却/已访问区域/揭示等级、世界纪事、子格视觉位置和两条 RNG 流的后续值全部一致；另断言版本不兼容、损坏 JSON、缺失存档被拒绝，主菜单 Continue 按钮可见性与 `has_save("auto")` 一致。

**D-64 平衡基线统计与事件密度校准（P0 剩余项 2～4）**

本轮新增 headless 平衡工具 `tests/balance_report.gd/.tscn`，自动跑完整局并统计事件数、触发来源、AI 意图、自然袭击与战斗蒙特卡洛。基线为 50 局 × 40 回合、5 名角色各 10 局；形状种子 `20261023 + i×7919`，生态种子 `20261026 + i×104729`，同批种子逐局可复现。模拟期间关闭自动存档与交互战斗，结束后恢复。

1. **触发参数**：POI 首次进入由 70% 改为 100%（10 个 POI 单局实际只走到 4～8 个，再掷概率会让 POI 份额过低）；首次进入未访问地形连通区域改为 60% 判定；wander 保留每 3 AP 13%，另在每回合开始加一次 24% 环境判定，补足低速角色少掷 AP 造成的缺口。四类触发仍共用优先级、队列、冷却与行动内预算。
2. **单局上限**：新增 `MAX_RANDOM_EVENTS_PER_RUN = 29`，终点守卫不计入且预留 1 个名额，因此含终点事件不超过 30。上限按「已开始 + 已入队」计算；达到后新随机触发直接忽略并写调试日志。未开始的队列事件跨回合保留，队列仍受 2 个容量限制，避免走过的地点被吞掉。`random_events_this_run` 写入存档并在读档时恢复。
3. **50 局结果（v1.6 重跑）**：平均 24.6 事件/局，中位数 26；44/50 落在 20～30，6 局低于 20，0 局高于 30，15 局触达 29 上限。触发来源为跨区域 23.3%、POI 18.0%、wander 58.7%；事件密度约每 10.0 AP / 4.43 格一次。分角色均值：林鸮 25.1、沙铠 23.2、薇拉 24.6、影 27.8、青蘅 22.4。速度高的角色更容易触碰上限，这是设计接受的「先跑完内容」边界，不再通过继续加事件突破 30；低于 20 的 6 局主要是低 AP 或短移动路线，属于抽样下界。
4. **AI 意图**：总体支援 43.0%、终点 17.8%、休息 22.8%、追击 12.3%、袭击 1.7%、探索 1.2%、侦察 1.2%。按阵营：友好支援 60.1% / 终点 15.9% / 休息 21.8%；中立休息 57.3% / 终点 34.7% / 探索 7.0%；敌对追击 67.2% / 终点 16.0% / 袭击 9.1% / 休息 7.7%。敌对追击占比高来自 MVP 两个敌对任务（影偷装备、薇拉施困）都要求先接近玩家；报告阈值按任务语义放宽（总体追击 5～15%、敌对追击 45～75%、中立休息 30～60%），不把任务驱动误判成异常。
5. **战斗与反击**：单次攻击命中 35.7%（大成功 5.1%），失败 64.3%（大失败 22.6%），平均伤害 0.79，攻击者平均 HP 代价 0.226。AI 袭击后不反击平均损失 0.80 HP、当场死亡 0.6%；花 1 AP 反击平均净损失 1.01 HP、对敌伤害 1.00、当场死亡 1.1%。玩家先手时敌方反击率 99.4%，玩家净损失 1.00、对敌伤害 1.00。决斗玩家胜 43.1%、敌方胜 40.4%、16.5% 未分胜负，平均 8.7 次出手。反击是「用 1 AP 换约 1 点敌方伤害」的交易，不再严格优于承受。
6. **反击次数修正**：AI 主动袭击已经用掉它本回合的出手，玩家选择反击后它不再顺势反击；只有玩家主动袭击时，存活且 AP ≥1 的敌方才会反击一次。此前允许二次反击会把反击变成负收益（玩家平均损失约 1.75 HP），与 D-58「反击后不再无限连锁」冲突。平衡脚本按同一规则统计。
7. **自然战斗与死亡**：50 局共 1980 个同伴回合，自然袭击 58 次（2.9%/回合），命中 11 次（19.0%），累计 20 伤害，袭击者付出 18 HP；平均每局 1.16 次 AI 袭击 + 1.52 次马匪伏击（事件检定，不走 `CombatRules`）。模拟机器人仅在 HP ≤50% 时休息、并规避必死选项，50 局死亡 1 次（2%）。这是「谨慎玩家」的下界，不能据此判定设计目标 20～30% 死亡率过高或过低；机器人也不会主动冲终点，49 局因 40 回合超时结束，因此本轮不产出胜率结论。真人或更激进策略的死亡率与胜率仍需试玩验证。
8. **可复现性**：平衡配置新增可选 `fixed_terrain_seed`（仅在 `randomize_seed = false` 时生效），让地图形状与生态都可固定；此前只固定形状种子，生态每局重掷，导致同一批种子跑出不同结果。运行命令见 README「验证」，报告同时写入 `user://balance_report.json`。
9. **测试口径**：冒烟测试继续覆盖事件预算、冷却、队列与读档，并新增单局随机事件上限、终点守卫豁免、`random_events_this_run` 存档恢复断言。平衡报告不加入常规冒烟，避免每次回归多跑数十局；调整触发/战斗参数后应至少重跑 50 局，确认事件中位数、触发份额与战斗三项（触发率、反击收益、死亡）没有越界。
10. **v1.7 重跑（P0 收口后）**：敌方偷窃即时判负加入后，50 局中 6 局因影偷走装备/补给提前结束（第 3～23 回合），其余 44 局超时，普通死亡 0、胜利 0；平均 23.1 事件/局、中位数 26，41/50 落在 20～30，17 局触顶。触发份额跨区域 24.5% / POI 18.2% / wander 57.2% 均在区间。AI 总体袭击 0.6%（低于旧诊断带 1～5%），但阵营内敌方袭击 6.1% 达标；下降来自影的偷窃任务成功即结束本局，以及敌方任务优先级，不按回归处理。中立侦察 7.1% 略高于旧带 0～5%，样本仅 212 次，暂不调权。该机器人不处理 A3 背包溢出，也不主动追回失物；真人试玩需重点观察影的早期判负是否过重。
11. **v1.8 重跑（复审修正后）**：同一批 50 局种子下，普通死亡 0、胜利 0、超时 50，**早期偷窃判负 0**（v1.7 为 6）。平均 24.4 事件/局、中位数 25，41/50 落在 20～30，14 局触顶；触发份额跨区域 22.3% / POI 17.1% / wander 60.6%，密度约每 10.2 AP / 4.58 格一次。AI 总体意图为支援 42.0%、终点 14.8%、休息 25.2%、追击 9.7%、袭击 1.6%、探索 4.7%、侦察 2.2%；中立分支为休息 39.6%、终点 21.4%、探索 20.3%、追击 16.3%、侦察 2.3%，敌方分支为追击 66.1%、袭击 16.7%、休息 8.6%、终点 8.6%，均落在按任务语义放宽后的诊断带内。2000 个同伴回合共 53 次自然袭击（1.06 次/局）。总体休息 25.2% 比旧诊断带上沿 25% 高 0.2 个百分点，视为采样波动；D-25 追回与 A3 溢出仍由机器人忽略，真人试玩需继续观察失物追回的实际使用率。

**D-65 正反馈闭环：结算摘要、可用消耗品、POI 发现、同伴里程碑与本局回顾（v1.6，A23）**

试玩反馈指出「玩了一局但看不到明确的正反馈」。诊断结果是：事件结果是一段平铺文本，物品进了背包却没有使用入口，POI 奖励依赖事件且不稳定，同伴好感只有数值或完全隐藏，结算页只给一句胜负原因。v1.6 按 A23 补五条闭环，全部只增强「已经发生的结果如何被看见和使用」，不改变选择前的信息边界，也不新增选择前剧透。

1. **事件结算摘要**：`EventManager._apply_effects()` 在原有 `messages` 之外维护 `rewards` / `costs` / `insights` 三个 `{text, kind, hint}` 数组；`_finish_resolution()` 统一复制为 `reward_entries` / `cost_entries` / `insight_entries`。`EventPanel` 只在检定或交易结算后渲染「◆ 收获 / ◇ 线索 / ◆ 代价」，并按条目 `kind` 着色；带 `hint` 的条目说明后续用途（装备、直接使用、交易材料等）。已经出现在摘要里的同文本 `messages` 不再在下方重复。失败/死亡提前返回也携带三类数组，保证 UI 不因空值回退。
2. **选择前仍不剧透**：摘要只在结果确定后生成；`_describe_choice()` 继续只返回选项、风险与禁用原因。测试同时断言选择前不存在 `preview` / `hint` / `warning`，选择后才出现物品名与代价。
3. **消耗品直接使用**：`GameManager.consumable_options(item_id)` 返回可用操作与禁用原因；`use_item(item_id, option)` 校验状态、物品存在与效果，补给支持 `hp` / `ap`，药水按 `removable_status_ids` 解除一个状态。被拒绝的使用（满 HP/AP、无目标、移动/事件中）不会移除物品；成功使用才消耗 1 件、写纪事、刷新背包并自动存档。背包页点击消耗品显示「使用」按钮，不再只展示说明。
4. **POI 首次发现保底奖励**：`EventManager._grant_poi_discovery()` 在首次踏足 POI 时、地点事件触发之前发放一份奖励：45% 补给、35% 5～9 金币、20% 药水；同时把 `_visited_pois[poi_id]` 置为已访问。奖励使用新的 `exploration` 随机流，因此不改变 `event` / `ai` 等既有确定性序列，便于平衡基线复现。重复踏入不会再次发放；读档沿用 `visited_pois` 恢复，因此不会刷奖励。
5. **探索进度可见**：`EventManager.get_visited_poi_count()` / `get_total_poi_count()` / `get_exploration_text()` 供 HUD 显示「探索 N/M」；首次发现奖励写入旅途纪事，并通过 `GameManager.world_notice` 弹出顶部提示。玩家不需要打开日志才能确认自己刚刚发现了什么。
6. **同伴羁绊与里程碑**：`CompanionAI.bond_label()` 按好感给出敌意/冷淡/谨慎/亲近/信赖，HUD 与暂停页的「关系」行始终显示定性标签，精确好感仍只在高情报等级显示。好感首次达到 +4 时 `check_favor_milestone()` 触发一次 `trust_supply`，由 `GameManager.apply_companion_favor()` 实际发放 1 份补给、写纪事与提示；里程碑在 `to_dict()` / `load_dict()` 中持久化，读档不会重复领取。
7. **本局回顾**：`GameManager.build_run_summary_text(win)` 汇总回合数、探索地点数、遭遇事件数、金币、行囊件数、装备、同伴关系（或倒下）与终点距离/胜利层级；HUD 在胜负结算页把它追加到失败/胜利原因下方，让玩家在重开前能回看整局积累。
8. **反馈通道统一**：纪事、顶部提示、HUD 回合信息、事件摘要、背包使用按钮与结算回顾共享同一份状态，不各自维护文案；新增奖励必须同时考虑「在哪里看见」和「怎么使用」。
9. **测试口径**：冒烟测试新增结算三类摘要存在性与内容、补给/药水成功与拒绝使用不消耗、POI 首次奖励恰好一份且二次踏入不重复、探索文本、同伴 +4 里程碑只发一次、羁绊标签不依赖高情报、里程碑存档往返、本局回顾胜负两版文案；边界点击测试改为从多边形共享边取样，避免 Voronoi 顶点导致的随机失败。v1.6 已重跑 50 局平衡报告：24.6 事件/局（中位数 26）、44/50 落在 20～30、三类触发份额与全部 AI 意图档位达标，新增 `exploration` 随机流未造成偏移。

**D-66 P0 收口：互斥胜负、A3 背包溢出与 D-25 失物追回（v1.7）**

本轮不新增设计玩法，只把 P0 验收中仍缺的边界补成可玩、可存、可回归的实现。

1. **敌方互斥目标**：`CompanionAI._complete_exclusive_task()` 统一记录任务完成与失败原因。影偷窃成功且当时为敌方时写入 `_player_defeated` 与 `_defeat_reason`；友方/中立则走 `_change_favor(-5)` 转敌，不立即失败。`GameManager._run_companion_turn()` 在同伴行动后读取 `player_defeated`，立即进入 `GAME_OVER` 并清除自动存档。薇拉的成功施困不立即判负，而在 `accept_run_end()` 的窗口（玩家到达终点时仍 `trapped`，或终局/超时未到达）结算；敌方在该窗口完成目标同样判负，友方/中立完成只转敌。林鸮、青蘅、沙铠的完成只改变任务/好感/阵营，不直接改写玩家结局。
2. **A3 背包溢出**：玩家背包按物品种类计 8 格，同种叠加不额外占格。`GameManager.grant_item(item_id, count, source)` 是所有玩法内物品奖励的统一入口；满格时写入 `pending_item_overflows` 并发出 `inventory_overflow_changed`，不直接丢弃。HUD 在序章、移动、事件、战斗、结算与背包页之外的安全边界自动打开背包页，玩家可点击背包物品丢弃 1 件收下新物品，或点「放弃」让新物品永久丢失；背包页在队列未清空前不能关闭。溢出队列随存档保存与恢复，读档后仍需完成取舍。POI、交易、事件、AI 偷窃与同伴里程碑不再直接调用 `player.add_item()`。
3. **D-25 失物追回**：影得手后记录 `_stolen_item_id`；玩家每回合可免费进行一次感知检定 DC 12（`2d6 + 感知 + 装备 + 状态`），不消耗 AP，每回合最多一次。成功从影的背包移除物品、经 `grant_item()` 归还玩家、影好感 −3（−5 下限截断），并发出骰子动画、纪事与顶部提示；不撤销影的 `_task_completed`。失败只消耗本回合的追查机会。背包页在失物存在时显示「追查失物（免费）」及本回合是否已尝试；`_recovery_attempt_round` 与 `_stolen_item_id` 均写入存档。
4. **AI 背包**：按 D-27 固定 3 格，自动丢弃顺序为非任务材料 → 非任务消耗品；任务物品与 `ai_task_protected` 物品永不自动丢弃。无格可腾时拒绝新物品，影的偷窃会因此把物品还回并保持任务未完成。
5. **测试口径**：冒烟测试新增直接与 GameManager 集成两层断言——敌方偷窃立即判负、友方/中立转敌不判负、薇拉窗口判负、青蘅满包失败与重试、林鸮最后三格/终点先揭示、沙铠可交易物与任务物品保护；A3 的 8 格满、同种叠加、第九种排队、错误丢弃拒绝、丢弃换入、放弃丢失与空队列拒绝；D-25 的低感知失败、同回合二次尝试拒绝、下回合成功、不耗 AP、好感 −3、任务不回溯、入口消失；存档往返恢复 `pending_item_overflows`、`_stolen_item_id` 与 `_recovery_attempt_round`。

**D-67 复审修正：移动上限、阵营阈值与边界清理（v1.8）**

本轮逐条复核队友复审与深玩报告，只修正确认可复现或与设计冲突的部分，不采纳超出 P0 或改动设计数值的建议（献祭折算检定加值、战斗 DC 改 7、玩家隐藏任务、事件扩到 30+、元进度）。

1. **单段路径成本封顶**：`MapData.MAX_SEGMENT_COST_DECI = 30.0`，玩家连续路径与 AI 格心近似共用。AI 用相邻格心直线估算成本，陡坡或长边会算出超过低 AP 角色整回合的数值（复现种子最坏单边 9.48 AP，来自 `131 → 273`），导致它每回合都判定“走不起”而永久留在原地。封顶保证任何角色每回合至少能跨过一段。玩家侧保留按实际笔迹连续扣费，只是单段不会再把多回合预算压进一小段路。
2. **阵营阈值**：`CompanionAI._faction_from_favor()` 改为设计 §11.3 的 `favor >= 3` 友方、`favor <= -3` 敌方，其余中立。旧实现的 ±2 会让影在两次失败后提前敌对，下一次得手直接判负。
3. **互斥目标强制转敌**：`_complete_exclusive_task()` 在友方/中立得手时先 `_change_favor(-5)`，再显式 `faction = "enemy"`。设计 §11.4 的“好感 −5 并转为敌方”是强制结果；高好感角色扣到 −2 时按普通阈值仍是中立，不能因此逃过转敌。
4. **影的初始状态与失败下限（A24）**：`ying_steal_gear` 初始阵营改为中立、好感 `[0, 1]`，任务未完成时失败结算后好感下限 −2。否则她在首次得手前就可能被失败推到敌方，随后一次成功立即判负，D-25 的追回窗口在多数开局中根本不会出现。任务完成后、事件或援助造成的敌对不受此保护。
5. **终点守卫出口**：`goal_guard` 增加无检定的「退开」选项，固定成功、不损 HP、后退 1 格且不进入终点，玩家不必靠献祭物品或硬闯才能离开。
6. **UI 旧状态清理**：`DiceOverlay.clear()` 递增令牌并终止补间，事件开始、非检定推进、背包/溢出页与游戏结束时清空；结算时隐藏底部行动栏。修复上一事件骰子淡出遮住新事件、以及游戏结束后底栏仍显示可操作按钮的问题。
7. **未知物品拒绝**：`GameManager.grant_item()` 先查 `DataManager.has_record("items", item_id)`，未知 ID 返回失败且不入包、不排队。此前错误数据会静默塞进背包，直到 UI 读定义时才报错。
8. **测试口径**：冒烟测试新增单段上限（原始最坏成本 > 30、封顶后 ≤ 30 且 ≤ 最慢角色单回合 AP）、12/24/48px 实际路径成本增长与封顶、未知物品不入包（含满包不排队）、影初始中立与中立追击意图、±3 阈值、单次失败仍中立、连续失败不能跳过 D-25、失物追回入口、友方高好感完成陷阱任务仍强制转敌、守卫「退开」无检定/无损/退格、骰子清理与结算底栏隐藏。平衡报告的中立/敌方意图诊断带按影的新追击语义同步调整。50 局复跑见 D-64 第 11 条。
